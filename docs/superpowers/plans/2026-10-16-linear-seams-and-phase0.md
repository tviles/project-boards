# project-boards Linear Plan 1: Provider Seams and Linear Phase 0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the code provider-neutral where a Linear backend will plug in (a neutral error, a provider-qualified board key, generalised content references, option colours and kinds, view filters, and a `Backend` enum at the sync and send seam), with GitHub behaviour unchanged; and run Linear phase 0 (pinned schema, testbed tooling, seed program, probes, findings).

**Architecture:** Four slices, each one PR into `main`. Slices 1–3 (Tasks 1–8) are refactors GitHub users cannot see: every existing test keeps passing, apart from constructor renames. Phase 0 (Tasks 9–14) is independent of them: it adds Linear's schema to `crates/queries`, offline-tested tooling in `tests/common/linear_testbed.rs`, and two cargo examples (a seed program and the probes) that run only against the testbed workspace, behind a guard. Plan 2 (written after the probes) builds the Linear client, wiring and the 0.4.0 release on these seams.

**Tech Stack:** Rust 2024 (MSRV 1.88), tokio, reqwest 0.13, graphql_client 0.16 (validation and variables only), serde_json hand decoding, ratatui 0.30, thiserror 2, toml 1, time 0.3, wiremock, insta, tempfile. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-15-linear-adapter-design.md` (read sections 3, 4, 5, 9, 10 and 12 before starting). The main spec, `docs/superpowers/specs/2026-09-30-project-boards-design.md`, still governs GitHub behaviour. The conventions follow `docs/superpowers/plans/2026-10-12-editing.md` (read its Global Constraints and Decisions).

**Out of scope (plan 2):** the Linear client (`src/linear/`), Linear credentials in the app (`LINEAR_API_KEY`, `linear_api_key_command`), the setup-screen change for several providers, the picker sections, CLI friendly forms, the filter evaluator (`model/filter.rs`), the `EditContext` read-only reason, the recorder scrubber, recorded Linear fixtures, live Linear tests, README and the 0.4.0 release.

### Plan-level decisions (flag any you disagree with before execution)

1. **Two plans.** This plan covers spec slices 1–3 and phase 0. Plan 2 (slices 4–7) is written after the probes, against measured facts (Tyler, 2026-10-16).
2. **Moved to plan 2, because nothing would use them yet:** the filter evaluator (spec slice 4), credentials per provider and the setup-screen change (spec slice 3), and the `EditContext` read-only reason (spec slice 3). Each has its first user in the Linear client or wiring.
3. **`SyncProfile` holds pages and the incremental mode only** (`full_page`, `poll_page`, `incremental`). The recent window and the in-flight limit affect edits only; Linear has none until 0.5, so they stay constants (`store::RECENT_WINDOW`, `ops::queue::MAX_IN_FLIGHT`) and move into the profile in the 0.5 plan.
4. **`BackendError`'s shape.** `NoCredentials`, `Unauthorized` and `MissingPermission` carry the provider, and their GitHub texts are unchanged word for word. `RateLimited { retry_after_secs }`, `Api(Vec<GraphqlErrorEntry>)`, `Network(String)` and `Decode(String)` carry no provider: they stay one-to-one with today's variants, so the rename is mechanical. Three texts lose the word "GitHub" and **need Tyler's approval**:
   - "rate limited by GitHub; retry in Ns" becomes "rate limited; retry in Ns";
   - "GitHub returned an error: …" becomes "the server returned an error: …" (the toast fallback "GitHub returned an error" in `ui/app/edit.rs` is untouched until plan 2 changes UI wording);
   - "could not decode GitHub's response: …" becomes "could not decode the response: …".
   No existing test asserts these three.
5. **No `remedy()` method.** `ui::app::setup_message` is already the one place that turns an error into the fix the user runs; it gains the Linear texts. The scope denials in `model::caps::Denial` (`NoProjectScope`, `NoRepoScope`) stay GitHub-worded: classic token scopes exist only on GitHub. (The spec's §5 sketch had `remedy()`; this is the same rule with less code.)
6. **`BoardKey::Github(GithubBoard)`.** Today's `BoardRef { owner, number }` struct is renamed `GithubBoard` and kept inside the enum, so the GitHub client keeps taking a struct with `owner` and `number`. `BoardKey` serializes as its string form.
7. **`ContentRef.key` is `Option<String>`.** It is set only when the provider names items with something other than `#number` (Linear: `ENG-123`). GitHub leaves it `None` and the label is still derived from `number`, so tests that zero `number` to make a placeholder keep working and no stored label can go stale.
8. **`ViewFilter` converts from strings.** `From<&str>` and `From<String>` give `ViewFilter::Github`, and `Display` prints the GitHub query (empty for Linear filters), so existing `view.filter = "…".into()` test lines compile unchanged. Code that needs the GitHub text calls `github_query()`.
9. **A Linear board key before Linear exists** (for example `--project linear:team:x` on this plan's build) fails to resolve with `NoCredentials { provider: Linear }`, which shows the Linear setup text. No request is sent.
10. **Phase 0 programs talk to Linear with plain `reqwest`.** They need the HTTP status and the `X-RateLimit-*` and `X-Complexity` headers, which the app's `Transport` hides. The request bodies still come from `graphql_client` operations, so every query is validated against the pinned schema.
11. **Phase 0 operations use scalar variables inside literal input objects** (`issues(filter: { team: { id: { eq: $teamId } } })`, `issueCreate(input: { teamId: $teamId, title: $title })`), like the GitHub mutations (editing plan Decision 8). No `IssueFilter` or `*Input` type is generated, and no `null` key reaches an input. Task 9 also tries one operation with an `IssueFilter` variable, to learn whether plan 2 can send built-in tab filters as variables (probe L10, a compile-time check).
12. **Linear cannot create cycles through the API** (`cycleCreate` is deprecated: "Cycle creation is not supported"). The seed enables cycles on team A and lets Linear create them.
13. **The seed renames the workspace's first team** to "Testbed A" (`TBA`) instead of creating a third team: the Free plan allows two teams, and Linear creates one at sign-up.
14. **Probe L10 is added to the spec's list:** whether `graphql_client` 0.16 can generate an operation with an `IssueFilter` variable from Linear's schema. Fallback: send such operations as raw requests whose text is still checked by a validated twin operation (decided in plan 2).

```rust
use crate::model::Provider;
use serde::Deserialize;

/// One entry of a GraphQL response's `errors` array.
#[derive(Debug, Clone, PartialEq, Deserialize)]
pub struct GraphqlErrorEntry {
    pub message: String,
    #[serde(rename = "type", default)]
    pub kind: Option<String>,
}

#[derive(Debug, Clone, PartialEq, thiserror::Error)]
pub enum BackendError {
    #[error("{}", no_credentials(.provider))]
    NoCredentials { provider: Provider },
    #[error("{}", unauthorized(.provider))]
    Unauthorized { provider: Provider },
    #[error("{}", missing_permission(.provider, .needed))]
    MissingPermission { provider: Provider, needed: Vec<String> },
    #[error("rate limited; retry in {retry_after_secs}s")]
    RateLimited { retry_after_secs: u64 },
    #[error("the server returned an error: {}", messages(.0))]
    Api(Vec<GraphqlErrorEntry>),
    #[error("network error: {0}")]
    Network(String),
    #[error("could not decode the response: {0}")]
    Decode(String),
}

impl BackendError {
    /// The variant's name, for logs that must not carry the server's message text.
    pub fn kind(&self) -> &'static str {
        match self {
            BackendError::NoCredentials { .. } => "NoCredentials",
            BackendError::Unauthorized { .. } => "Unauthorized",
            BackendError::MissingPermission { .. } => "MissingPermission",
            BackendError::RateLimited { .. } => "RateLimited",
            BackendError::Api(_) => "Api",
            BackendError::Network(_) => "Network",
            BackendError::Decode(_) => "Decode",
        }
    }
}

fn no_credentials(provider: &Provider) -> String {
    match provider {
        Provider::Github => "no GitHub token found: set GH_TOKEN or run `gh auth login`".into(),
        Provider::Linear => {
            "no Linear API key found: set LINEAR_API_KEY or linear_api_key_command".into()
        }
    }
}

fn unauthorized(provider: &Provider) -> String {
    match provider {
        Provider::Github => {
            "GitHub rejected the token (401 Unauthorized); run `gh auth login`".into()
        }
        Provider::Linear => {
            "Linear rejected the API key; create a new one in Linear's settings".into()
        }
    }
}

fn missing_permission(provider: &Provider, needed: &[String]) -> String {
    match provider {
        Provider::Github => format!(
            "the token is missing the {} scope; run `gh auth refresh -s project`",
            needed.join(", ")
        ),
        Provider::Linear => "Linear refused the request: the API key cannot see this board".into(),
    }
}

fn messages(errors: &[GraphqlErrorEntry]) -> String {
    errors
        .iter()
        .map(|e| e.message.as_str())
        .collect::<Vec<_>>()
        .join("; ")
}
```

```rust
/// A GitHub board as users name it: `owner/number`, e.g. `acme/3`.
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct GithubBoard {
    pub owner: String,
    pub number: u32,
}

impl fmt::Display for GithubBoard {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}/{}", self.owner, self.number)
    }
}

/// Any board. GitHub's is written `owner/number` as it always was, so state written by
/// earlier versions still parses; Linear's is `linear:project:<id>` or `linear:team:<id>`,
/// by UUID because team keys and project names can be renamed.
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
#[serde(into = "String", try_from = "String")]
pub enum BoardKey {
    Github(GithubBoard),
    LinearProject { id: String },
    LinearTeam { id: String },
}

impl BoardKey {
    pub fn github(owner: impl Into<String>, number: u32) -> Self {
        Self::Github(GithubBoard {
            owner: owner.into(),
            number,
        })
    }

    pub fn provider(&self) -> crate::model::Provider {
        match self {
            Self::Github(_) => crate::model::Provider::Github,
            Self::LinearProject { .. } | Self::LinearTeam { .. } => crate::model::Provider::Linear,
        }
    }

    pub fn as_github(&self) -> Option<&GithubBoard> {
        match self {
            Self::Github(b) => Some(b),
            _ => None,
        }
    }

    /// A file-system-safe key, e.g. `acme__3` or `linear__team__<id>`.
    pub fn key(&self) -> String {
        match self {
            Self::Github(b) => format!("{}__{}", b.owner, b.number),
            Self::LinearProject { id } => format!("linear__project__{id}"),
            Self::LinearTeam { id } => format!("linear__team__{id}"),
        }
    }
}

impl fmt::Display for BoardKey {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Github(b) => b.fmt(f),
            Self::LinearProject { id } => write!(f, "linear:project:{id}"),
            Self::LinearTeam { id } => write!(f, "linear:team:{id}"),
        }
    }
}

/// A Linear id as it may appear in a key: letters, digits and `-` (UUIDs, and team keys
/// until plan 2 resolves those to ids).
fn linear_id(id: &str) -> Option<String> {
    (!id.is_empty() && id.chars().all(|c| c.is_ascii_alphanumeric() || c == '-'))
        .then(|| id.to_string())
}

impl FromStr for BoardKey {
    type Err = String;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        if let Some(rest) = s.strip_prefix("linear:") {
            let bad = || format!("expected linear:project:ID or linear:team:ID, got `{s}`");
            return match rest.split_once(':') {
                Some(("project", id)) => linear_id(id)
                    .map(|id| Self::LinearProject { id })
                    .ok_or_else(bad),
                Some(("team", id)) => linear_id(id)
                    .map(|id| Self::LinearTeam { id })
                    .ok_or_else(bad),
                _ => Err(bad()),
            };
        }
        let bad = || format!("expected OWNER/NUMBER, got `{s}`");
        let (owner, number) = s.split_once('/').ok_or_else(bad)?;
        let number: u32 = number.parse().map_err(|_| bad())?;
        if owner.is_empty() || owner.contains('/') || number == 0 {
            return Err(bad());
        }
        Ok(Self::github(owner, number))
    }
}

impl From<BoardKey> for String {
    fn from(b: BoardKey) -> String {
        b.to_string()
    }
}

impl TryFrom<String> for BoardKey {
    type Error = String;
    fn try_from(s: String) -> Result<Self, Self::Error> {
        s.parse()
    }
}
```

```rust
    /// A hex colour (`#rrggbb`, `rrggbb`, `#rgb`, `rgb`), as Linear sends; anything else is
    /// `Unknown`.
    pub fn from_hex(value: &str) -> Self {
        let h = value.strip_prefix('#').unwrap_or(value);

    }
```

```rust
//! The Linear testbed for the seed program, the probes and (plan 2) the live suite: which
//! workspace it is, where its key comes from, and a guard that stops before any request
//! reaches another workspace. Included with `#[path]` (tests/linear_testbed.rs, examples).
#![allow(dead_code)] // each includer uses a different part

use serde_json::Value;

pub const ENDPOINT: &str = "https://api.linear.app/graphql";
const KEYCHAIN_SERVICE: &str = "project-boards-linear-testbed";

/// Where the testbed key comes from. Never `LINEAR_API_KEY`: that is the user's own workspace.
#[derive(Debug, PartialEq)]
pub enum KeySource {
    Env(String),
    Keychain(Vec<String>),
}

pub fn key_source(env: impl Fn(&str) -> Option<String>) -> KeySource {
    match env("PB_LINEAR_TESTBED_KEY")
        .map(|k| k.trim().to_string())
        .filter(|k| !k.is_empty())
    {
        Some(key) => KeySource::Env(key),
        None => KeySource::Keychain(
            ["security", "find-generic-password", "-s", KEYCHAIN_SERVICE, "-w"]
                .map(String::from)
                .to_vec(),
        ),
    }
}

pub fn resolve_key() -> Result<String, String> {
    let missing = || {
        format!("no testbed key: set PB_LINEAR_TESTBED_KEY or add the Keychain item `{KEYCHAIN_SERVICE}`")
    };
    match key_source(|k| std::env::var(k).ok()) {
        KeySource::Env(key) => Ok(key),
        KeySource::Keychain(argv) => {
            let out = std::process::Command::new(&argv[0])
                .args(&argv[1..])
                .output()
                .map_err(|e| format!("{}: {e}", argv[0]))?;
            if !out.status.success() {
                return Err(missing());
            }
            let key = String::from_utf8(out.stdout)
                .map_err(|_| "the Keychain item is not UTF-8".to_string())?
                .trim()
                .to_string();
            if key.is_empty() { Err(missing()) } else { Ok(key) }
        }
    }
}

/// tests/linear-testbed.toml: invented names only.
#[derive(Debug, Clone, PartialEq)]
pub struct Testbed {
    /// The workspace's URL key (linear.app/<url_key>).
    pub url_key: String,
    pub team_a: String,
    pub team_b: String,
    pub project: String,
}

pub fn testbed_from(text: &str) -> Result<Testbed, String> {
    let t: toml::Table = text.parse().map_err(|e| format!("linear-testbed.toml: {e}"))?;
    let field = |name: &str| {
        t.get(name)
            .and_then(|v| v.as_str())
            .filter(|s| !s.trim().is_empty())
            .map(String::from)
            .ok_or_else(|| format!("linear-testbed.toml needs `{name}`"))
    };
    Ok(Testbed {
        url_key: field("url_key")?,
        team_a: field("team_a")?,
        team_b: field("team_b")?,
        project: field("project")?,
    })
}

pub fn testbed() -> Testbed {
    let text = std::fs::read_to_string("tests/linear-testbed.toml")
        .expect("tests/linear-testbed.toml (run from the repository root)");
    testbed_from(&text).unwrap_or_else(|e| panic!("{e}"))
}

/// Stops unless the key reaches the testbed. The other workspace is not named: it may be a
/// real one.
pub fn check_workspace(seen: &str, testbed: &Testbed) -> Result<(), String> {
    if seen == testbed.url_key {
        Ok(())
    } else {
        Err(format!(
            "the key reaches another workspace, not the testbed `{}`; stopping before any other request",
            testbed.url_key
        ))
    }
}

/// A response as Linear sent it: status, the rate and complexity headers, and the body.
#[derive(Debug, Clone, PartialEq)]
pub struct Raw {
    pub status: u16,
    pub headers: Vec<(String, String)>,
    pub body: Value,
}

impl Raw {
    pub fn header(&self, name: &str) -> Option<&str> {
        self.headers
            .iter()
            .find(|(n, _)| n.eq_ignore_ascii_case(name))
            .map(|(_, v)| v.as_str())
    }

    pub fn data(&self) -> &Value {
        &self.body["data"]
    }

    /// `errors[].extensions.code`, in order.
    pub fn error_codes(&self) -> Vec<String> {
        self.body["errors"]
            .as_array()
            .map(|errors| {
                errors
                    .iter()
                    .filter_map(|e| e["extensions"]["code"].as_str().map(String::from))
                    .collect()
            })
            .unwrap_or_default()
    }
}

pub struct Linear {
    http: reqwest::Client,
    key: String,
}

impl Linear {
    /// No workspace check: only for probe L6's deliberately bad key.
    pub fn unguarded(key: String) -> Self {
        let http = reqwest::Client::builder()
            .user_agent("project-boards-testbed")
            .timeout(std::time::Duration::from_secs(30))
            .build()
            .expect("reqwest client builds");
        Self { http, key }
    }

    /// The testbed client: resolves the testbed key and checks the workspace before
    /// returning, so no other request can reach another workspace.
    pub async fn connect(testbed: &Testbed) -> Result<Self, String> {
        use project_boards_queries::linear::{TestbedViewer, testbed_viewer};
        use graphql_client::GraphQLQuery;
        let me = Self::unguarded(resolve_key()?);
        let raw = me
            .post(&TestbedViewer::build_query(testbed_viewer::Variables {}))
            .await?;
        let seen = raw.data()["viewer"]["organization"]["urlKey"]
            .as_str()
            .ok_or_else(|| format!("the viewer query failed (HTTP {})", raw.status))?;
        check_workspace(seen, testbed)?;
        Ok(me)
    }

    pub async fn post(&self, body: &impl serde::Serialize) -> Result<Raw, String> {
        let response = self
            .http
            .post(ENDPOINT)
            .header("Authorization", &self.key)
            .json(body)
            .send()
            .await
            .map_err(|e| e.without_url().to_string())?;
        let status = response.status().as_u16();
        let headers = response
            .headers()
            .iter()
            .filter(|(n, _)| {
                let n = n.as_str();
                n.starts_with("x-ratelimit") || n == "x-complexity"
            })
            .map(|(n, v)| (n.as_str().to_string(), v.to_str().unwrap_or("").to_string()))
            .collect();
        let body = response.json().await.unwrap_or(Value::Null);
        Ok(Raw {
            status,
            headers,
            body,
        })
    }
}
```
